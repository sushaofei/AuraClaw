# M5 实时体验与可靠交付测试报告

## 结论

M5 已实现 Runtime Event Producer SDK、Kafka Runtime Event Bus、授权 SSE Gateway、短期重放与
背压，以及由 Canonical Event Transactional Outbox 驱动的可靠 Result Delivery。实时链路失败
不会破坏 Session 事实；最终通知不依赖 Kafka，Delivery Worker 停机后可从 PostgreSQL Job 恢复。

## 覆盖范围

- Producer SDK 自动分配同 Stream sequence，拒绝 `secret` visibility 和超限消息，递归拦截敏感
  字段，并按阈值合并 Token Delta。
- Kafka Producer 使用 Root Session 分区键；服务级 Consumer Group 消费并在进入可恢复 Replay
  Buffer 后提交 Offset。真实 Kafka 完成生产—消费往返。
- SSE 订阅先按 tenant 查询 Session；外租户不能猜测 ID 订阅。`Last-Event-ID` 在保留期内补齐，
  过期产生 `stream.reset` 与 Query URL。
- 每连接队列有界；非关键进度可采样，关键审批/终态会替换队列内低价值事件而不阻塞生产者。
- `run.completed` 等可交付 Canonical Event 在同一 Event Store append 中写入独立 delivery Outbox。
- `(event_id, sink_id)` 生成稳定 `delivery_id`；重复 Outbox/Event 不创建第二个业务 Job。
- PostgreSQL Delivery Job 经首次 503 进入 retry_wait；关闭并重建 Store/Worker 后使用同一 ID 成功，
  Attempt History 保留两次证据。
- Webhook 发送稳定 Idempotency-Key、时间戳和 HMAC-SHA256；429/5xx/timeout 可重试，永久 4xx
  直接失败。
- Parent Session Sink 通过 Canonical Event 交付，Circuit Breaker 和 DLQ 行为均有自动化覆盖。
- `delivery.attempting/retrying/succeeded/failed/dead_lettered` 回写 Session 并投影到 Task/Result
  Query；Runtime Event 丢失不影响这些状态。

## 数据库与回滚

- `0006_m5_streaming_delivery.sql` 新增 Sink Config、Attempt History、Job 恢复索引、稳定 Sink 唯一
  约束和 Task Delivery 查询字段。
- `0006_m5_streaming_delivery.down.sql` 提供对应回滚，并恢复旧 Job 唯一约束。
- Canonical Event 仍是业务事实源；Runtime Replay Buffer 和 Task Projection 可删除，Delivery Job
  Store 只保存可恢复投递过程与证据。

## 已知边界

- 当前 Kafka 集成采用单服务级 Ingestor；多 Gateway 实例的内部 Connection Router/PubSub 通过
  现有 Replay/Subscription 端口扩展，不为每个浏览器建立 Kafka Consumer。
- Webhook Secret Resolver 是 Credential/Vault 边界，生产部署必须接入受控 Credential Proxy；
  测试使用静态 Resolver，但 Secret 不进入 Job 或事件。
