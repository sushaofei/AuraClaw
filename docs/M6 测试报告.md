# M6 测试报告

## 结论

M6“可靠性、观测与发布门禁”通过。统一 Trace Context、结构化日志、核心 Metrics、Audit Event
Store、主动告警和 Session Timeline 已形成可定位闭环；Telemetry 保留、Artifact GC、Projection
Poison/Delivery DLQ 运维和灰度回滚均有可执行入口。Canonical Event 仍是唯一任务事实源，观测数据
不参与业务状态决策。

## 自动化覆盖

- Trace/Audit/Metric/Alert 共享 root、session、run、event、command、tool、runtime、delivery、
  approval 关联字段；Timeline 可串联展示且按 tenant 隔离。
- Canonical Event 经 Outbox 自动、幂等派生组件 Span、高风险 Audit 和可靠性指标；Telemetry 故障
  不阻断业务 Projection 或 Canonical API。
- Projection lag、lease lost、unknown side effect、delivery DLQ 四类规则自动产生告警。
- 结构化日志、Trace attributes 和 Audit metadata 在写入前递归脱敏，已知 Secret 扫描零命中。
- Artifact 到期 GC 保留仍被引用的 Hash 对象；Telemetry 按独立保留策略清理。
- Projection Poison 与 Delivery DLQ 支持受租户限制的状态查看和人工重投。
- 架构总览的恢复、幂等、DAG 追踪、Projection 重建、SSE 重连、Delivery 恢复、审批绑定和
  Secret 隔离完成标准均映射到自动化回归。
- 数据库短断/幂等重试、Projection gap、Runtime 四故障点、Lease 接管、工具 unknown、Delivery
  5xx/DLQ 的 M1～M6 故障注入测试全部纳入全量回归。
- 200 个并发 admission 产生 200 个独立 Session，内存基准的 append 路径 P95 小于 100 ms。

## 容量与恢复判定

M6 沿用 MVP SLO：append P95 < 100 ms、Projection freshness P95 < 2 s、task start P95 < 5 s、
Runtime recovery P95 < 30 s、SSE P95 < 1 s、Webhook 在 Sink 可用时 99%/60 s。发布门禁使用指标
而非 Runtime Event 推测最终结果；容量变化时可调整负载模型，但不得降低幂等、fencing、审批绑定
和 Secret 零泄漏标准。

## 已知边界

内存适配器用于开发和确定性故障测试；生产可靠性结论依赖 PostgreSQL、Kafka 和外部 Sink 的部署
监控。Audit/Trace 原始 Payload 不入普通日志，需要全文调试时必须写受控 Artifact 并经过审批和
访问审计。
