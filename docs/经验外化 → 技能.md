**问题**：实现智能体的自主运转，带来了流程设计与推理负担（Procedural Burden of Agency）。
**解法**：通过技能外化过程（Skill Externalization），将过程性经验从大模型内部剥离，转化为可复用的系统资产。其完整生命周期包含三个理论阶段（唤起 → 选择 → 执行），在系统工程上对应四步落地的流水线（获取 → 制品化 → 激活调度 → 运行时执行）。
# 什么是技能（经验外化）？
**外化的对象**：流程化的经验（Procedural Expertise），而非孤立的接口。
**什么是流程化的经验**
- 工具（Tools）负责**提供动作**。
- 协议（Protocols）负责**规范动作**如何被描述和调用。
- 技能（Skills）负责**沉淀**一类任务的**执行逻辑**。
**外化经验的三个核心组件**：
- 操作流程（Operational Procedures）→ 结构
- 决策启发（Decision Heuristics）→ 策略
- 规范性约束（Normative Constraints）→ 边界
**经验外化**：`结构（怎么做） + 策略（怎么选） + 边界（不能做什么） → 沉淀为可复用的 【专家级实操经验（know-how）】。`
## 1. 操作流程（Operational Procedures）
**什么是操作流程**：对一项复杂的工作分解后的步骤、阶段、依赖关系和停止条件，即任务主干（Task Skeleton）。决定了智能体**怎么做**。
**为什么外化**
- **目标**：减少大模型对任务执行逻辑的即兴发挥所导致的任务失败。
- **痛点**：大模型推理的不确定性所引发的过程级别的不稳定性（如遗漏步骤、死循环等）。
**经验总结**
- CoT [Chain-of-Thought Prompting Elicits Reasoning in Large Language Models, 2023]
- ReAct [ReAct - Synergizing Reasoning and Acting in Language Modes, 2023a]
- Skill Systems [SOP-Agent - Empower General Purpose AI Agent with Domain-Specific SOPs, 2025]
## 2. 决策启发（Decision Heuristics）
**什么是决策启发**：相较于沉淀任务主干的操作流程，决策启发沉淀的是对任务分支路径（Branch）做选择的经验法则与捷径。决定了智能体在**什么条件下做什么选择**。
**为什么外化**：
- **目标**：降低大模型的认知负载，将高频的局部判断转化为低延迟、低成本的硬逻辑，提升系统吞吐量。
- **痛点**：如果让大模型每次都从头推理所有条件，不仅消耗海量 Token，且容易在复杂条件分支中产生逻辑幻觉。
**经验总结**
- 专家经验总结 [Annual Review of Psychology, 2011]
## 3. 规范性约束（Normative Constraints）
**什么是规范性约束**：判定在流程中的遇到一个动作是否越界、是否符合业务与安全合规要求的条件边界。决定了智能体**在什么边界内被允许做**。
**为什么外化**
- 被动应对 → 主动防御
- 概率模型 → 确定性阻断
- 黑盒运行 → 合规自证
**经验总结**：
- 访问限制 [Schick et al., 2023 (Toolformer)], [Chen et al., 2021 (Codex)]
- 范围限制 [Bai et al., 2022b (Constitutional AI / Anthropic)]
- 领域特定操作规则 [Madaan et al., 2023 (Self-Refine)], [Chen et al., 2021 (Codex)]
- 可追溯性期望 [Wei et al., 2023], [Madaan et al., 2023]
# 如何实现技能（经验外化）？
技能（经验外化）的核心在于将过程经验转化为在运行时**可发现**、**可加载**、**可解释**、**可绑定**和**可执行**的形式。
可以将智能体系统的经验外化分成**两层**：
- **表示层**：决定一个技能在逻辑上如何被定义和界定
	- **描述**：清晰地描述该技能的功能、逻辑与输入输出。
	- **界定**：划定该技能的边界、使用场景及约束条件。
- **运行时层**：决定一个技能在任务执行期间，能否真正作为一种可复用的能力发挥作用
	- 何时**加载**：根据当前任务状态触发并调入内存。
	- 依赖哪些**记忆**：提供必要的上下文或历史状态作为运行条件。
	- 绑定哪些**资源**：与具体的工具、文件或子智能体进行动态连接。
## 1. 规约（Specification）- 表示层
[Ling et al., 2026]
*定义世界观。系统用统一的语言来描述“我会做什么”。*
### 什么是规约？
规约是技能的**声明式契约**（Declarative Specification Artifacts），它剥离了具体的底层代码实现，专门用于向系统和人类描述该技能的属性。
可以通过三个维度，**形式**、**内涵**和**作用**全面地理解规约。
### 规约的形式
在工程实践中，它最终沉淀为**声明式的产物**（Declarative Specification Artifacts）。典型的格式包括`SKILL.md`、`YAML/JSON Manifest`、`JSON Schema`或指令说明文件。
### 规约的内涵
它本质上是**接口文档**，而非**接口实现**。它不包含执行逻辑（代码、脚本），而是严格定义技能：
- 功能边界：能做什么？适用于什么场景？即：What & When。
- 输入/输出约束：Schema 契约。
- 正反例：明确告诉模型什么情况下该用或不该用。
### 规约的作用
面向**智能体引擎**：作为元数据，让大模型在极低的 Token 成本下快速完成技能的**发现**、**检索**与**路由**。
面向**人类与工程治理**：作为静态制品，它是可被安全团队和产品经理**审查**（inspected）、**讨论**（discussed）、和**版本控制**（governed）的对象，从而保证系统的安全可控。
### 什么是健康的规约？
至少涵盖五类信息：
- 能力边界（Capabilities）
- 适用范围（Scope/Context）
- 前置条件（Preconditions：执行前系统必须具备什么状态）
- 执行约束（Execution Constraints：比如超时限制、重试次数、副作用限制）
- 正反示例（Examples & Counterexamples：降低大模型幻觉）
在设计智能体工具时，一定要先提交一份**YAML**或**Markdown**格式的技能规约进行评审。
## 2. 发现（Discovery） - 运行时层
[Zheng et al., 2025a], [Ross et al., 2025]
*解决“广度”问题。从千万个技能中，精准匹配当前需要的 N 个。*
### 什么是发现？
发现是智能体系统的**动态注册**与**选择性检索**机制。在工程实践中，因为受限于大模型的上下文窗口、推理成本和注意力，智能体不可能在每次任务中无差别地加载所有可用技能，因此必须实现按需检索。
### 发现的形式
在架构设计上，发现机制通常由两部分组成
- **注册机制**：技能被发布到**本地仓库**、**组织级仓库**或**平台级市场**。
- **检索机制**：结合**语义检索**、**结构化元数据匹配**以及**任务分解**来实现。
### 发现的内涵
发现是高维度的**经验匹配**，要求检索出的技能必须与当前任务在**语义**和**操作结构**上匹配。
### 发现的作用
发现让智能体系统可以动态加载技能，通过输入当前的任务目标、上下文状态和环境条件，从庞大的技能库中筛选出最相关的候选集合，极大地降低大模型的认知负荷和幻觉率。
### 什么是健康的发现机制？
需要考虑五个维度：
- 主题相似度：技能描述与任务目标的贴合度。
- 任务复杂度：技能的颗粒度是否匹配当前任务的层级。
- 环境假设：技能运行所需的依赖环境当前是否满足。
- 操作约束：如耗时、权限、资源消耗等是否超标。
- 风险条件：在当前上下文执行该技能是否有安全隐患。
## 3. 渐进式披露（Progressive Disclosure） - 运行时层
[Xu and Yan, 2026b], [Anthropic, 2025]
*解决“深度”问题。控制信息密度，保护大模型脆弱的上下文窗口和推理信噪比。*
### 什么是渐进式披露？
渐进式披露是针对大模型上下文窗口的**分段式加载策略**。智能体系统**发现**一个技能后，只在真正需要时才加载更深的细节。
### 渐进式披露的形式
在工程实践中，它通常表现为多层级的结构化呈现：
- 浅层：仅提供技能**名称**与简短**描述**。
- 中层：暴露类似 Manifest 的信息，包括**使用条件**、**前置依赖**和**主要约束**。
- 全量层：加载完整的执行指南，包括**详细步骤**、**异常处理**、**正反示例**和**支持文件**。
### 渐进式披露的内涵
渐进式披露将是否需要更多技能细节转化为一个独立的**运行时决策**，强制让技能的**信息密度**与当前任务的**复杂度**相匹配。
### 渐进式披露的作用
面向**模型推理**：保持大模型在规划阶段的专注度与推理信噪比。
面向**系统性能**：降低每次请求的 Token 消耗与首字延迟（TTFT）。
### 什么是健康的渐进式披露机制？
至少包含两个设计：
- 技能规约本身在物理结构上就是**分层存储**的。
- 智能体具备从浅入深、从选择到执行的决策能力。
## 4. 执行绑定（Execution Binding） - 运行时层
[Anthropic, 2024]
*划定“物理边界”。让大模型的“高层战略规划”和底层工具的“物理干活”解耦。*
### 什么是执行绑定？
执行绑定是将技能转化为当前环境中具体的可执行操作的**翻译**与**连接**的过程。如果没有这一步，技能只是一份理论上可读，但实际上无法使用的静态产物。
### 执行绑定的形式
在工程实践中，它通常具象化为一个**中间解释层**或**运行时底座**：
- 负责将技能连接到底层的物理实现，如：工具、文件操作、接口、子智能体或 Shell 命令。
- 基于 Schema 的接口协议，例如 MCP 充当的连接模型与底层资源的绑定层。
### 执行绑定的内涵
执行绑定是**解耦**与**动态决议**，划定了智能体架构中三个核心概念的绝对边界：
- 工具：提供底层的、具体的**可执行操作**。
- 协议：定义这些操作如何被描述和调用。
- 技能：提供更高维度的**策略**，负责将这些底层工具组合来完成可复现的任务。
### 执行绑定的作用
面向**系统执行**：决定在当前的上下文中，应该激活哪些技能步骤、绑定哪些底层原语、触发哪些分支条件，以及哪些约束应该优先执行。
面向**架构拓展**：防止技能退化为硬编码的工具。通过绑定层，技能规约可以保持通用，而底层的工具实现可以随时替换。
### 什么是健康的执行绑定机制？
- 清晰的职责分离：技能负责编排策略、工具负责物理执行。
- 动态的运行时解释器：能够根据当前上下文，动态判断条件分支和约束优先级。
- 标准协议：发现与调用解耦。
## 5. 组合（Composition） - 运行时层
[Wang et al., 2023a], [Yu et al., 2025]
*提供“无限扩展性”。让无数的原子技能像乐高积木一样，组合出解决复杂业务的终极形态。*
### 什么是组合？
组合是将复杂任务分解为多个能力包协同合作的机制。与原子化的底层工具不同，技能可以参与到高阶的结构化协调中。
### 组合的形式
- 串行执行
- 并行分工
- 条件路由
- 递归/嵌套调用
### 组合的内涵
组合是对过程性经验的高阶复用。
### 组合的作用
面向**业务逻辑**：告别庞大且僵化的端到端单体流程。
面向**工程治理**：赋予智能体系统**可维护性**、**可替换性**和**可审计性**。
### 什么是健康的组合机制？
- 非单体化设计：拒绝将复杂业务写成从头到尾的全能型技能，要按照专业边界拆解、解耦为高内聚的子技能。
- 标准的运行时接口：统一规范，使系统调度器能够无缝支持串行、并行和嵌套编排。
- 状态流转的可观测性
# 技能（经验外化）来自哪里？
[Xu and Yan, 2026b], [Wang et al., 2023a]
技能来自获取与进化。技能不是一次性的静态设计步骤，而是一个**持续的进化过程**。技能的获取与进化为智能体系统提供了一条将**过去成功的行为模式**转化为**未来可复用的经验**的系统化路径。
## 获取与进化的形式
技能的来源分为四种路径：
- 人工编写（Authored）：最常见且稳定的初始基建（如 SOP 模板、`SKILL.md`）。它不仅提供初始化能力，更是工程师通过观察失败案例、不断补充约束条件以修复 Bug 的干预接口。
- 蒸馏提取（Distilled）：从大模型的历史交互轨迹和情景记忆中归纳。当某些成功的执行结构在不同任务中反复出现时，系统将其抽象提炼为稳定的过程单元。
- 自主发现（Discovered）：智能体通过与环境的自主交互（探索、执行反馈、自我验证）发现新的行为模式，并将其固化为显式技能。
- 组合进化（Composed）：将底层小技能组合成复杂工作流，一旦这种组合被反复验证有效，该组合策略本身就会被打包封装为一个全新的高阶技能。
## 获取与进化的内涵
获取与进化是将经验外化为可复用能力的转化过程，将临时的运行时记忆升维转化为稳定的可执行技能。
## 获取与进化的作用
面向**系统能力**：使系统具备自驱生长能力，技能库从扁平孤立的列表，演化为深度嵌套的层级树。
面向**工程运维**：提供一种机制，使得每一次线上部署的失败都能收敛转化为技能库中一条清晰的约束规则，实现闭环迭代。
## 什么是健康的获取与进化机制？
系统需要构建一套进化飞轮：
- 证据提供：记忆模块负责记录并提供轨迹成功或失败的数据依据。
- 价值评估：评估器负责判定哪些临时经验有价值，可以被晋升为全局技能。
- 部署准入：必须通过标准协议的审查，决定一个候选的新技能是否真正安全且能够部署到实机环境。
# 技能可靠性的边界
## 边界1：语义与行为的错位
#### 什么是语义与行为错位？ 
大模型在自然语言层面上完全理解了意图，但在最终调用底层工具时，产生了与业务期望不符的物理执行动作。 
#### 错位的形式 
- **参数幻觉**：编造了接口不需要或不存在的参数。 
- **约束逃逸**：字面上遵守了提示词，但生成的代码或操作越过了业务红线（如删除了不该删除的数据库字段）。 
- **过度泛化**：将模糊的用户指令强行映射到高危操作上。 
#### 错位的内涵
自然语言的**模糊性/灵活性**与底层强类型系统的**死板性/严谨性**之间的阻抗不匹配。 
#### 错位的影响
导致系统发生静默失败（Silent Failure），即程序没有报错，但业务数据已经被污染或逻辑已经跑偏。
#### 什么是健康的防错位机制？ 
- **强类型校验器（Type Enforcement）**：在执行前，必须用代码（如 Pydantic）对大模型输出的 JSON/参数进行严格的结构验证。 
- **执行前确认（Dry-run / HITL）**：对于高危写操作，执行前必须由人类确认（Human-in-the-loop）或在沙盒中进行模拟运行。
## 边界2：环境变迁与过期
#### 什么是环境变迁与过期？ 
一个曾经完美运行的技能，因为外部环境的变化或底座模型的切换，突然丧失了执行能力。
#### 过期的形式 
- **接口腐烂**：第三方接口更新了字段或鉴权方式。 
- **DOM 漂移**：网页结构改变导致 RPA 或爬虫类技能失效。 
- **模型依赖**：基于 GPT-4 调试好的技能，无缝迁移到开源模型时效果断崖式下跌。 
#### 过期的内涵
技能并不是纯粹的抽象逻辑，而是高度耦合于特定外部状态与特定模型能力的**条件化产物**。 
#### 过期的影响
让系统陷入维护地狱（Maintenance Hell），随着技能库变大，系统整体的可用性呈指数级下降。 
#### 什么是健康的防过期机制？ 
- **声明式依赖**：每个技能必须显式声明其依赖的外部环境版本和适用的 LLM 模型。 
- **自动化健康探针（Health Check）**：像管理软件依赖一样管理技能库，利用 CI/CD 定期运行测试用例，一旦外部环境变动导致测试不通过，技能自动标红下线。
## 边界3：组合带来的安全风险
#### 什么是组合安全风险？ 
两个在独立测试时绝对安全的技能，被大模型自主串联在一起时，引发了意料之外的系统漏洞。 
#### 风险的形式 
- **提示词注入传导（Prompt Injection）**：大模型调用“读取外部邮件”技能读入了一段恶意代码，随后又调用“执行 Bash”技能将该代码运行。 
- **越权访问（Privilege Escalation）**：利用低权限技能获取的信息，欺骗高权限技能执行操作。 
#### 风险的内涵 
复杂系统的**非预期涌现（Emergent behavior）**。在多模块交互的边界，原有的局部安全假设会完全失效。 
#### 风险的影响
破坏系统沙盒，导致严重的数据泄露、合规违规或服务器被控制。 
#### 什么是健康的防组合风险机制？ 
- **零信任数据流转**：技能与技能之间传递的数据必须经过清洗，不能包含可执行的指令。
- **互斥锁与权限隔离（Mutex & Isolation）**：建立上下文级拦截器（例如：规定在同一个任务会话中，`Web_Search` 技能与 `Execute_SQL` 技能绝对互斥，不可同时激活）。
## 边界4：长上下文导致的注意力降级
#### 什么是注意力降级？ 
在多步骤、长周期的任务中，随着上下文（Context）越来越长，大模型对技能的遵循程度和执行精度出现断崖式下降。 
#### 降级的形式 
- **目标遗忘**：沉溺于解决某个技能的局部报错，忘记了用户最初的全局任务。 
- **指令忽略（Lost in the Middle）**：模型忽视了写在 Prompt 中间位置的约束条件。 
- **死循环调用**：不断重复调用同一个报错的技能，无法跳出。 
#### 降级的内涵 
大模型底层注意力机制（Attention Mechanism）受限于上下文窗口大小的**物理极限**。信息密度过高会稀释推理能力。 
#### 降级的影响
彻底锁死了智能体解决复杂、长链路任务的上限，使其只能处理“一问一答”的简单任务。
#### 什么是健康的防降级机制？ 
- **动态上下文修剪（Context Pruning）**：当技能执行完毕并返回结果后，立即将冗长的技能说明和中间日志从 Context 中剔除。 
- **状态摘要（State Summarization）**：只保留高浓度的“当前任务进度摘要”，始终保持上下文窗口的极度纯净。
# 技能的系统级协同
## 协同 1：技能与记忆
- 核心机制：框架不盲目加载技能，而是先查询系统记忆（历史记录、过往结果、特定用户上下文）。
- 协同作用：记忆模块为技能提供**情境证据**。它决定了当前加载哪个技能、传入什么参数、走哪个逻辑分支。没有记忆模块的协同，技能检索会退化为的关键字匹配；通过记忆协同，同一个技能在面对不同上下文时，能表现出不同的自适应行为。
## 协同2：技能与协议
- 核心机制：技能只负责描述应该做什么（What），而协议模块负责定义具体怎么做（How）。
- 协同作用：框架通过标准的协议接口（如 OpenAPI schemas、子智能体委派契约、文件操作API）将大模型的意图映射为可执行的物理动作。框架在这里充当了**路由器**和**翻译官**，确保技能的每一步都落在合法的执行底座上。
## 协同3：技能与治理规则
- 核心机制：在生产环境中，框架强制在技能外部包裹一层治理逻辑，包括敏感操作权限校验、高危动作人工审批（HITL）、审计日志记录、以及多步执行失败时的回滚机制。
- 协同作用：安全管控不是写在技能内部的，而是框架赋予的属性。一个在开发沙盒里测试绝对安全的技能，在生产环境中必须经过治理模块的严格约束，以防止不可预知的越权。
## 协同4：技能与进化闭环
- 核心机制：框架是连接运行时操作与技能进化的桥梁。技能执行的轨迹、成功率、报错模式和人类纠偏数据，都会被框架重新写入记忆库中。
- 协同作用：这形成了系统的飞轮效应。执行结果不再是被丢弃的一次性日志，而是作为评估证据，触发旧技能的修正、废弃，或者催生出新的候选技能。
# 技能的认知本质
**问题**：为什么大模型加上外挂技能后，会变得更聪明、更稳定？
**观点**：技能是一种认知产物，它对系统产生了三个根本性的影响：
- **改变认知任务的性质**：徒手 → 借助工具。大模型无需从其黑盒参数中痛苦且概率性地**回忆**或**捏造**操作步骤，而是变成了直接阅读外部清晰的技能说明书并**按图索骥**。
- **实现能力的重新分配**：重复造轮子 → 按需组装与调度。大模型的算力不再消耗于**死记硬背**复杂的业务 SOP，而是 100% 释放给它最擅长的事情——理解当前环境上下文、推理意图，并精准**调度**外部现成的能力资产。
- **完成知识的外化**：黑盒不可控 → 白盒可治理。将最容易产生幻觉的**过程性知识**（How-to）从模型内部剥离出来，固化为系统外部可审计、可测试、可复用的工程资产。
