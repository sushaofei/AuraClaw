# M2 Managed Runtime 与控制平面测试报告

## 测试范围

本报告覆盖 GitHub issue #2 和实施计划 M2 的功能与架构验收，验证对象包括：

- Control State Store 的 runnable queue、原子 claim、lease、单调 fencing token、assignment、
  heartbeat、capacity、cancel 和 checkpoint。
- 两个 Orchestrator 并发竞争、Runtime provision、cancel、lease heartbeat 和 reconcile。
- Agent Harness 的 run_id、lease、budget、deadline、cancel、checkpoint 和恢复路径。
- Session、Model、Tool、Runtime Event 四类 Runtime 端口。
- Model Gateway Provider 替换与 Secret 隔离。
- 完整模型输出的 Canonical Event 持久化和 Token Delta 的 Runtime Event 分流。

## 自动化用例设计

| 场景 | 注入或竞争方式 | 预期结果 |
|---|---|---|
| 双 Orchestrator 竞争 | 并发 claim 同一 runnable item | 只有一个 assignment 和一条 `run.scheduled` |
| Lease 失效 | Lease 到期后由第二 Runtime 接管 | fencing token 递增，旧 Session/Tool 请求被拒绝 |
| 模型调用前崩溃 | `before_model` 注入异常 | 新 Runtime 使用稳定 model_call_id 恢复 |
| 模型完成后崩溃 | `after_model` 注入异常 | 从 checkpoint 恢复，不重复调用 Provider |
| 工具执行前崩溃 | `before_tool` 注入异常 | 已持久化工具意图，恢复后执行一次 |
| 工具执行后崩溃 | `after_tool` 注入异常 | 使用稳定 invocation id/result 恢复，不重复副作用 |
| Provider 替换 | 相同 ModelRequest 连接两个 Adapter | Session 与 Orchestrator 无需修改 |
| Runtime Bus 故障 | Token Delta 发布持续失败 | 完整模型输出和 `run.completed` 仍进入 Canonical Log |
| PostgreSQL 控制面 | 两连接并发 claim、lease、capacity、checkpoint | 原子竞争、容量上限、恢复和 fencing 均成立 |

## 结论与剩余边界

M2 验收场景全部通过。Runtime Event Bus 不承担结果交付；Session Canonical Event 仍是唯一任务
事实源。真实工具审批、Sandbox、Artifact、大结果引用、Credential Proxy 和外部副作用幂等属于
M3，不在本阶段伪装为已完成能力。
