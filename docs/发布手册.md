## 0. 先选模板

| 场景 | Compose 文件 | 说明 |
|------|--------------|------|
| 本地 / 联调 | `compose.services.yml` | 端口直出，便于调试；MCP 在 `action-hands:8006` |
| DEV_SERVICE / 预发 | `compose.production.yml` | 部署在 `10.244.16.131`；Secret 文件 + Ingress `:8080` |
| 生产 | `compose.production.yml` | Secret 文件挂载、内部网络、Nginx ingress `:8080` |

不要混用两套 env。本地 debug 用 `.env.debug`（来自 `.env.debug.example`）；生产 / DEV_SERVICE 用 `.env.production`（来自 `.env.production.example`，勿提交）。

## A. 本地多服务发布（`compose.services.yml`）

### A1. 前置

```bash
# 仓库根目录
cp .env.debug.example .env.debug   # 本地 12 入口 / compose.services 联调
docker --version
docker compose version
```

关键变量（按需）：

- 主库：`HANDS_DATABASE_URL` 等角色 DSN，或统一 storage 相关项
- Runtime → Hands：`AURACLAW_HANDS_URL=http://action-hands:8006`（Compose 里已写死给 runtime）
- Model Skill（可选）：`AURACLAW_MODEL_SKILL_*` + `MYSQL_DB_*`（只读 `ct_model_*`）
- 价格洞察 Tool（可选）：`AURACLAW_PRICE_INSIGHT_*`

### A2. 构建并启动

```bash
docker compose -f compose.services.yml up --build -d
# 需要统一入口时：
docker compose -f compose.services.yml --profile ingress up --build -d
```

### A3. 验收

```bash
docker compose -f compose.services.yml ps

# 各服务 ready（示例）
curl -sf http://127.0.0.1:8000/health/ready   # task-api
curl -sf http://127.0.0.1:8006/health/ready   # action-hands（内部 Hands HTTP）
curl -sf http://127.0.0.1:8004/health/ready   # agent-runtime

# 有 ingress 时
curl -sf http://127.0.0.1:8080/health/ready
```

MCP 所在容器：

```bash
docker compose -f compose.services.yml logs --tail 100 action-hands
```

Runtime 应指向 `http://action-hands:8006`，不要把 Hands 入口改到 runtime 容器。

### A4. 更新单个服务（热修）

```bash
docker compose -f compose.services.yml up -d --build --no-deps action-hands
docker compose -f compose.services.yml up -d --build --no-deps agent-runtime
```

### A5. 回滚 / 停止

```bash
# 回到上一镜像 tag（若你打了 tag）
docker compose -f compose.services.yml up -d --no-build

# 停栈
docker compose -f compose.services.yml down
```

## B. 生产发布（`compose.production.yml`）

### B1. 前置检查

```bash
docker --version          # Engine ≥ 20.10
docker compose version    # Compose v2

docker network inspect auraclaw-platform >/dev/null 2>&1 || \
  docker network create auraclaw-platform

# 镜像已就绪（digest 或不可变 tag）
docker image inspect "${AURACLAW_IMAGE:-auraclaw:s5}" >/dev/null
```

确认：

1. 若尚无 `.env.production`：`cp .env.production.example .env.production`，填入不可变镜像与真实密钥（0600，不进 Git）
2. DB 角色已授权：`deploy/mysql/roles.sql` 或 `deploy/postgres/roles.sql`
3. Kafka / SeaweedFS / Vault / 模型出口可从 `auraclaw-platform` 访问
4. Secret **不**写进 Compose、镜像、命令行

### B2. 物化 Secret + 预检

```bash
uv run python scripts/materialize_compose_secrets.py \
  --env-file .env.production --output-dir .runtime/compose-secrets

uv run python scripts/compose_preflight.py --env-file .env.production
```

Secret 目录权限：目录 `0700`，文件 `0600`。

### B3. 数据库迁移（先于应用）

MySQL（默认）：

```bash
docker compose --env-file .env.production \
  -f compose.production.yml --profile migrate run --rm migrate \
  migrate status --directory /app/migrations/mysql

docker compose --env-file .env.production \
  -f compose.production.yml --profile migrate run --rm migrate \
  migrate up --target 0016 --directory /app/migrations/mysql
```

PostgreSQL：目录改为 `/app/migrations`，并设 `AURACLAW_MIGRATIONS_DIRECTORY=/app/migrations`。

规则：只做 expand 迁移；发布窗口内不删 N-1 仍依赖的列/事件字段。

### B4. 启动应用

```bash
docker compose --env-file .env.production \
  -f compose.production.yml pull

docker compose --env-file .env.production \
  -f compose.production.yml up -d --wait --remove-orphans

docker compose --env-file .env.production \
  -f compose.production.yml ps

curl --fail http://127.0.0.1:8080/health/ready
```

### B5. 发布后冒烟（最少集）

按顺序确认：

1. Ingress ready：`curl --fail http://127.0.0.1:8080/health/ready`
2. `action-hands` healthy（内部 Hands Gateway）
3. `agent-runtime` healthy，且能连 `http://action-hands:8006`
4. 一条只读任务 / 价格洞察 canary（隔离租户）
5. 看 Canonical Result 落库；SSE 失败不代表任务失败

常用远程命令（本机 `.host.env` 的 `AURACLAW_HOST` = DEV_SERVICE `10.244.16.131`）：

```bash
./scripts/remote_compose.sh ps
./scripts/remote_compose.sh logs action-hands
./scripts/remote_compose.sh restart action-hands
```

完整 DEV_SERVICE 步骤见 [DEV_SERVICE 部署手册](./DEV_SERVICE部署手册.md)。

### B6. 简单回滚（非蓝绿）

数据库不 down migration。应用回滚到上一镜像：

```bash
# 1. 把 .env.production 里 AURACLAW_IMAGE 指回上一 digest/tag
# 2. 重新拉起
docker compose --env-file .env.production \
  -f compose.production.yml up -d --wait --remove-orphans

curl --fail http://127.0.0.1:8080/health/ready
```

需要零停机切流时，走 S5 蓝绿流程（另起 `auraclaw-green` project → canary → 切流 → 停 blue）。

## C. 与 MCP / Skill 相关的发布注意

| 组件 | 容器 | 职责 |
|------|------|------|
| 内部 Hands Gateway | `action-hands` | Runtime 唯一 Hands 入口：`/internal/v1/hands/*` |
| Runtime | `agent-runtime` | 只持有 `HttpHandsClient`，不持远端 URL/Secret |
| Model Skill 编译发布 | 跑在 `action-hands` 内 | 读 `ct_model_*` → 编译 Skill → 写入 Registry |
| 价格洞察 Tool | 默认也在 `action-hands` | 本地 ToolRegistry；若迁 Java 则经远端 MCP Egress |

发版涉及 Skill / Tool 时：

1. 先保证 `action-hands` 起来且 ready
2. 确认 Model Skill 配置：`AURACLAW_MODEL_SKILL_SOURCE_ENABLED`、只读 MySQL、签名 key
3. 生产关闭 Draft：`AURACLAW_MODEL_SKILL_INCLUDE_DRAFTS=false`
4. 改 Tool schema 必须 bump version，避免 Catalog 对账因 digest 漂移失败

## D. 停止发布的条件

出现任一情况立刻停发 / 回滚：

- 迁移 checksum drift 或 status 异常
- `/health/ready` 持续失败
- `action-hands` 起不来导致 Runtime 无 MCP
- Policy / Credential fail-open 或 Secret 出现在日志
- Canary 任务无 Canonical Result / 重复副作用
