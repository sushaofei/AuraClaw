# AuraClaw 文档

本目录只保留当前仍有维护价值的文档。阅读时先按用途选择入口，不要把实施记录或分享材料当作架构真源。

## 文档导航

| 用途 | 入口 | 内容 |
|---|---|---|
| 理解系统边界与关键设计 | [架构](./architecture/README.md) | 系统组件、ADR、核心机制、代码组织 |
| 接入 AuraClaw | [开发与接入指南](./guides/README.md) | 公开 API、身份、MCP、AuraMCP |
| 部署、发布与排障 | [运行手册](./operations/README.md) | 开发环境、生产部署、扩缩容、观测与发布 |

| 查表或准备分享 | [参考资料](./reference/README.md) | 数据库表、技术分享材料 |

## 真源优先级

出现不一致时，按以下顺序处理：

1. `architecture/system/` 与已接受的 ADR 定义系统边界和不变量；
2. 代码、迁移和公开契约定义当前实现；
3. 接入指南与运行手册说明如何使用和运维当前实现；
4. `development/implementation/` 只解释某次能力落地，不覆盖架构真源；
5. `reference/` 仅用于查阅和分享。

## 维护规则

- 新文档必须放入明确的用途目录，不再平铺到 `docs/` 根目录。
- 同一主题只保留一个现行入口；阶段完成后把稳定结论并入架构、指南或运行手册。
- 测试数量、一次性联调步骤和完成态清单不单独长期保存；阶段证据记录在
  [开发阶段校验清单](./development/stage-gates.md) 和 Git 历史中。
- 过期方案不建立常驻“坟场”；确有审计价值时依赖 Git 历史恢复。
