## 编写约定

- 每篇文档聚焦一个核心设计问题。
- 先给出关键心智模型，再说明正常链路、异常链路和关键不变量。
- 明确区分业务事实、派生视图、运行控制与实时信号。
- 机制说明应对应当前代码和架构文档，避免只描述理想设计。
- 涉及历史缺陷时，记录问题根因、修复方式及防止回归的不变量。
- 新文档使用两位编号，例如 `02 ...md`、`03 ...md`。
