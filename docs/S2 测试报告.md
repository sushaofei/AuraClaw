# S2 12 个入口与本地多进程拓扑测试报告

日期：2026-07-22
Issue：[正式开发：拆分为可横向扩展的生产服务部署边界（12 服务）](https://github.com/sushaofei/AuraClaw/issues/12)

## 结论

S2 验收通过。一个 AuraClaw 镜像可按 12 个独立命令启动，具备独立端口、对象图、健康检查、
Worker 生命周期和优雅停机；Task API 与 Streaming Gateway 的公开路由已拆分。

S2 只建立进程与部署拓扑，不提前宣称 S3 的唯一写入者、独立数据库角色或全部远程 Client
迁移完成。Runtime 与 Delivery 的跨服务执行循环将在 S3 接入 owner API 后启用。

## 交付范围

- 12 个生产 CLI 入口与 8000–8011 默认端口；`auraclaw serve` 保留为开发组合入口。
- Task API、Streaming Gateway、Session HTTP、Action Hands MCP 以及 8 个独立服务/Worker 进程。
- `/health/live`、`/health/ready`、硬依赖配置状态、ASGI lifespan 和 SIGTERM 排空。
- 单镜像非 root Dockerfile、12 服务 Compose、Nginx Task/Streaming 路由分流。
- 外部 SeaweedFS 配置接线；Compose 不重复部署用户已有的 SeaweedFS。
- [S2 多进程部署运行说明](./S2%20多进程部署运行说明.md)。

## 容器与停机 Smoke

使用构建出的 `auraclaw:s2-test` 镜像启动 Policy 服务并映射测试端口。`/health/ready` 返回
200；执行 `docker stop` 后日志依次出现 Uvicorn shutdown、application shutdown complete 和
finished server process，证明 SIGTERM 经 lifespan 完成优雅退出。测试容器随后移除。

## 安全、存储与迁移结论

- 镜像使用固定非 root 用户 UID 10001；构建上下文排除 `.env`、虚拟环境、缓存和本地数据。
- `.env.example` 的 Lease、workload token、SeaweedFS credential 均为空占位符；未读取、打印或
  提交真实 `.env`。
- 生产 Session、Hands、Model Gateway、Artifact Service 缺少硬依赖时 readiness 为 503，响应
  不含 Secret 或 API Key 值；开发内存后端明确显示为 `development-memory`。
- Artifact Service 使用现有外部 SeaweedFS endpoint；生产对象存储 Adapter 与 metadata owner
  的最终接线属于 S3。
- S2 可回滚至 development combined composition；S1 的契约、Lease/Fencing、MCP 与 Secret
  隔离规则保持不变。
