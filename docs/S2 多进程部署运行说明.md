# S2 多进程部署运行说明

## 范围

S2 将同一 AuraClaw 镜像暴露为 12 个独立进程入口，并建立独立生命周期、健康检查、端口和
Ingress 路由。S2 不宣称数据库/凭证边界迁移完成：兼容期 direct Store 装配在 S3 删除。

## 服务与端口

| 服务 | 命令 | 默认端口 |
|---|---|---:|
| task-api | `auraclaw api run` | 8000 |
| session | `auraclaw session run` | 8001 |
| projection-worker | `auraclaw projection relay --watch` | 8002 |
| orchestrator | `auraclaw orchestrator run` | 8003 |
| agent-runtime | `auraclaw runtime run` | 8004 |
| model-gateway | `auraclaw model-gateway run` | 8005 |
| action-hands | `auraclaw hands run` | 8006 |
| policy | `auraclaw policy run` | 8007 |
| credential-proxy | `auraclaw credential-proxy run` | 8008 |
| artifact-service | `auraclaw artifact run` | 8009 |
| streaming-gateway | `auraclaw streaming run` | 8010 |
| delivery-worker | `auraclaw delivery run` | 8011 |

命令均支持 `--host`、`--port`。`auraclaw serve` 拉起 12 个入口，并默认再开本地 Ingress
`:8080`（`AURACLAW_INGRESS_PORT`），分流规则与生产 Nginx 相同。关闭请设
`AURACLAW_INGRESS_ENABLED=false`。

Runtime 与 Streaming Gateway 是独立进程，因此 Runtime Event 必须使用共享 SQL 或 Kafka。
`auraclaw serve` 会拒绝“内存存储 + 内存事件后端”的组合，防止 SSE 订阅静默收不到事件。
默认 `.env.dev.example` 使用本机 Kafka；已有共享 SQL 的调试环境也可使用数据库 Replay Bus。

## 生命周期与健康

- `/health/live` 仅回答进程是否存活；进入 shutdown 后返回 503。
- `/health/ready` 检查该服务的硬配置依赖，不输出 URL 凭证、API Key 或 Secret 值。
- Worker 由 ASGI lifespan 创建；SIGTERM 后设置 stop event，等待当前循环退出，再由 Uvicorn
  完成连接排空。
- Projection Worker 在 PostgreSQL profile 下执行实际 Outbox relay；Orchestrator 执行 Control
  expired lease recovery。Assignment/Runtime/Delivery 的远程协作在 S3 切换稳定 Client 后启用。
- Model Gateway 缺少 Provider 配置、生产 Session 缺少 Lease Key、生产 Hands 缺少 workload
  token、生产 Artifact 缺少 SeaweedFS 时 readiness 为 503。

## SeaweedFS

Compose 假设 SeaweedFS 已部署，不创建第二套存储。Artifact Service 从环境读取：

```text
AURACLAW_ARTIFACT_BACKEND=seaweedfs
SEAWEEDFS_HOST
SEAWEEDFS_S3_PORT
SEAWEEDFS_ACCESS_KEY
SEAWEEDFS_SECRET_KEY
SEAWEEDFS_BUCKET
SEAWEEDFS_REGION
SEAWEEDFS_USE_SSL
SEAWEEDFS_PATH_STYLE
```

容器连接宿主机服务时使用 `host.docker.internal`；连接集群服务时使用其内部 DNS。Access/Secret
Key 只注入 Artifact Service 的生产部署。S2 不读取或记录真实 `.env` 值。

## Ingress

本地 `auraclaw serve` 默认在 `:8080` 提供与生产相同的分流，供 Java Runtime 智问代理使用：

- `/v1/streams/*` → `streaming-gateway:8010`，关闭代理缓冲并延长 SSE read timeout。
- 其他 `/v1/*` 和健康/运维路径 → `task-api:8000`。

Compose 可选 Nginx profile：

```bash
docker compose -f compose.test.yml --profile ingress up --build
```

## 回滚

停止 `compose.test.yml` 后可恢复 `auraclaw serve`。该回滚只改变 composition，不回滚 S1
契约、Session allowlist、Lease/Fencing、MCP 或 Secret 隔离规则。生产数据库迁移在 S2 不适用。
