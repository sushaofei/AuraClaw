## 浏览器冒烟

使用内存后端和生产构建产物完成：

1. 页面加载并恢复非敏感 API/tenant/actor 配置。
2. `live` 返回 `ok`，`ready` 返回 `ready`，页面显示 API online。
3. 创建任务返回 Session ID，页面随后自动读取完整 Task View。
4. Projection 在创建后显示 `v2`，无需手动刷新。
5. 请求历史记录健康检查、任务创建与 Task Query，并展示 status、耗时和 traceparent。

M7.1 使用同一生产构建与内存协议后端补充验证：

1. 智能问答收到两个 `model.output.delta` 后按顺序合并，重复事件不会重复展示。
2. 流断开时保存 Event cursor，重连请求携带 `Last-Event-ID`。
3. Task 完成后自动读取权威 Result，并显示“流式内容与 Result 已核对”。
4. 创建任务页完整展示脱敏 Query 请求、`202 Accepted`、Task View 和最终 Result。
5. Result 首次按 `Retry-After` 轮询，完成后保存 `ETag`；手动刷新命中 `304 Not Modified`。
6. 两个页面的 Hash 路由可直接恢复，浏览器控制台无错误。

M7.2 针对真实联调中“智能问答没有流式数据”的问题补充验证：

1. 修复前，本地前端对 API 的 `OPTIONS` 预检返回 `405`；直接调用 API 后任务持续 `pending`，
   SSE 三秒收到 0 字节。
2. 修复后，本地来源 CORS 预检返回 `200`，允许身份、幂等、版本、游标和条件查询 Header，并
   暴露 `ETag`、`Retry-After` 与 `traceparent`。
3. 纯内存开发 Runtime 经 Runnable Queue、Orchestrator、fencing 和 Agent Harness 执行，不由
   API 或前端伪造终态。
4. 真实前后端浏览器验证中，问答处于 `generating` 时已收到 56 个字符；完成后累计 162 个字符，
   Task 为 `completed`，页面显示“流式内容与 Result 已核对”。
5. 浏览器控制台无错误；联调不使用 Mock API。

## 安全与架构

- 前端只使用公开 HTTP/SSE API，不导入 `auraclaw.*`。
- Runtime Event 在 UI 中明确标注为非权威信息。
- Secret 不写入 localStorage、URL、控制台或持久请求历史。
- 复制 curl 会移除敏感 Header，并递归脱敏常见敏感字段。
- 高风险写操作展示 tenant/session 并二次确认。
- `.env`、`.history`、`node_modules`、构建产物、缓存和临时预览脚本不在交付范围。
