## 2. Schema 总览

| Schema | 作用 |
| --- | --- |
| `session_core` | 会话事实层，保存 Canonical Event、幂等记录、快照与投递 Outbox。 |
| `projection` | 可重建读模型与投影运行状态。 |
| `control` | 运行时调度与控制面，包括队列、分配、租约、检查点、取消请求。 |
| `delivery` | 结果投递与重试。 |
| `security` | 工具权限、调用幂等、凭证引用与使用审计。 |
| `artifact` | 产物元数据与访问审计。 |
| `observability` | Trace、Metric、Audit、Alert 与保留策略。 |

## 3. session_core

### 3.1 `session_core.session_head`

- 用途：保存每个 Session 聚合的当前版本号，是事件追加时的并发控制锚点。
- 主键：`(tenant_id, session_id)`。
- 关键字段：
  - `root_session_id`：根会话 ID。
  - `aggregate_version`：当前聚合版本。
  - `updated_at`：最后更新时间。
- 典型使用：
  - `PostgresEventStore.append()` 在写入事件前 `FOR UPDATE` 锁定该行并校验 `expected_version`。

### 3.2 `session_core.canonical_event`

- 用途：系统唯一事实源，保存规范化会话事件。
- 主键：`event_id`。
- 唯一约束：`(tenant_id, session_id, aggregate_version)`。
- 关键字段：
  - `root_session_id` / `session_id` / `run_id`：事件所属会话与运行实例。
  - `event_type`、`payload`：事件类型与载荷。
  - `actor`、`correlation_id`、`causation_id`：审计与链路追踪上下文。
  - `visibility`、`schema_version`：可见性与事件结构版本。
- 索引：
  - `canonical_event_root_idx (tenant_id, root_session_id, occurred_at)`，便于按根任务聚合读取事件。
- 典型使用：
  - `PostgresEventStore.load()` / `load_all()` 读取事件流。
  - `PostgresCollaborationProjection.project()` 按 `root_session_id` 回放协作 DAG。

### 3.3 `session_core.command_dedup`

- 用途：命令幂等去重，避免同一命令被重复执行。
- 主键：`(tenant_id, operation, command_id)`。
- 关键字段：
  - `operation`：命令所属操作。
  - `response`：上次执行结果快照，命中幂等时直接返回。
- 典型使用：
  - `PostgresEventStore.append()` 先查此表，命中后直接返回历史响应。

### 3.4 `session_core.outbox`

- 用途：事务性 Outbox，驱动投影与结果投递。
- 主键：`outbox_id`。
- 唯一约束：`(event_id, destination)`。
- 关键字段：
  - `destination`：当前已见取值有 `projection`、`delivery`。
  - `payload`：待发布事件内容。
  - `publish_attempt`、`next_attempt_at`、`published_at`：重试与完成状态。
- 索引：
  - `outbox_pending_idx (next_attempt_at, outbox_id) WHERE published_at IS NULL`。
- 典型使用：
  - `PostgresEventStore.pending_outbox()` 拉取投影待处理项。
  - `PostgresEventStore.pending_delivery_outbox()` 拉取投递待处理项。

### 3.5 `session_core.snapshot`

- 用途：Session 状态快照，加速重放。
- 主键：`(tenant_id, session_id, aggregate_version)`。
- 关键字段：
  - `schema_version`：快照结构版本。
  - `state`：聚合状态 JSON。
- 典型使用：
  - `PostgresEventStore.get_snapshot()` / `save_snapshot()`。

## 4. projection

### 4.1 `projection.task_view`

- 用途：任务主读模型，面向查询接口输出当前任务视图。
- 主键：`(tenant_id, session_id)`。
- 关键字段：
  - 基础任务信息：`root_session_id`、`run_id`、`goal`、`status`、`progress`、`current_stage`。
  - 协作信息：`role`、`parent_session_id`、`lineage`。
  - 结果信息：`result_summary`、`result_ref`、`artifact_refs`、`error`。
  - 投递信息：`delivery_status`、`delivery_id`、`delivery_attempt_count`、`delivery_response_summary`。
  - 投影游标：`source_version`、`source_event_id`、`projected_at`。
- 索引：
  - `task_view_root_idx (tenant_id, root_session_id, status)`。
- 典型使用：
  - `PostgresTaskProjection.project()` 增量更新该表。
  - 查询网关和 API 读取该表提供任务状态。

### 4.2 `projection.projector_checkpoint`

- 用途：记录投影器每个分区的处理检查点。
- 主键：`(projector_id, partition_id)`。
- 关键字段：
  - `checkpoint`：通常保存版本号、事件 ID 等 JSON 游标。
  - `updated_at`：最后更新时间。
- 典型使用：
  - `PostgresTaskProjection.project()` 在成功投影后刷新 task 投影检查点。

### 4.3 `projection.processed_event`

- 用途：投影幂等控制，避免同一事件被同一投影器重复消费。
- 主键：`(projector_id, event_id)`。
- 典型使用：
  - task / collaboration 等投影器在处理前先插入，插入失败即说明已处理。

### 4.4 `projection.poison_event`

- 用途：隔离无法被投影器识别或处理的异常事件。
- 主键：`(projector_id, event_id)`。
- 关键字段：
  - `reason`：隔离原因。
  - `payload`：原始事件载荷。
  - `quarantined_at`、`resolved_at`：隔离与解决时间。
- 典型使用：
  - `PostgresTaskProjection.project()` 遇到未知事件类型时写入该表。

### 4.5 `projection.approval_view`

- 用途：审批读模型，承载工具调用审批的查询视图。
- 主键：`(tenant_id, approval_id)`。
- 关键字段：
  - `session_id`、`run_id`：关联任务与运行。
  - `action_digest`、`tool_name`、`redacted_arguments`：待审批动作摘要。
  - `risk`、`reason`、`expected_effect`：风险与原因说明。
  - `allowed_decisions`、`assigned_approvers`、`policy_version`、`expires_at`。
  - `status`、`decision`、`feedback`：审批过程与结果。
  - `source_version`、`source_event_id`、`projected_at`：投影来源。
- 索引：
  - `approval_session_digest_idx (tenant_id, session_id, action_digest, policy_version, status)`。
- 典型用途：
  - 查询某任务下待审批项，或按动作摘要匹配重复审批场景。

### 4.6 `projection.collaboration_view`

- 用途：协作 DAG 读模型，描述根任务及子任务之间的分工、依赖、评审与产出。
- 主键：`(tenant_id, session_id)`。
- 关键字段：
  - `root_session_id`、`parent_session_id`、`role`、`task_key`、`goal`。
  - `dependency_ids`、`owner`、`status`、`runnable`。
  - `output_contract`、`budget`。
  - `result_ref`、`artifact_refs`、`target_session_id`、`review_decision`、`evidence_refs`。
  - `source_version`、`source_event_id`、`projected_at`。
- 索引：
  - `collaboration_root_idx (tenant_id, root_session_id, parent_session_id)`。
  - `collaboration_runnable_idx (tenant_id, runnable, root_session_id) WHERE runnable = true`。
  - `collaboration_task_key_idx (tenant_id, root_session_id, task_key)` 唯一索引。
- 典型使用：
  - `PostgresCollaborationProjection.project()` 每次按 `root_session_id` 重建整棵 DAG 视图。

## 5. control

### 5.1 `control.runtime_lease`

- 用途：运行资源租约表，用于实现租约抢占和 fencing token。
- 主键：`resource_id`。
- 关键字段：
  - `lease_id`：租约实例 ID。
  - `lease_owner`：持有者。
  - `expires_at`：过期时间。
  - `fencing_token`：防脑裂令牌。
  - `lease_version`：租约版本。
- 典型使用：
  - `PostgresControlStateStore.acquire_lease()` / `renew_lease()` / `release_lease()`。

### 5.2 `control.runnable_item`

- 用途：待调度任务队列表。
- 主键：`task_id`。
- 唯一约束：`(tenant_id, session_id, source_version)`。
- 关键字段：
  - 任务定位：`tenant_id`、`root_session_id`、`session_id`、`run_id`。
  - 调度属性：`priority`、`available_at`、`queue_partition`、`status`、`claimed_by`、`attempt`。
  - 运行要求：`required_capability`、`role`、`deadline`、`budget`。
- 索引：
  - `runnable_claim_idx (queue_partition, priority DESC, available_at, task_id) WHERE status = 'queued'`。
- 典型使用：
  - `PostgresControlStateStore.enqueue()` 入队。
  - `claim()` 按优先级与时间窗口抢占任务。

### 5.3 `control.assignment`

- 用途：记录任务与 Runtime 的实际分配关系。
- 主键：`task_id`。
- 关键字段：
  - 关联信息：`tenant_id`、`root_session_id`、`session_id`、`run_id`、`runtime_id`、`lease_id`。
  - 状态信息：`assignment_status`、`assigned_at`、`started_at`、`completed_at`、`deadline`。
  - 并发保护：`fencing_token`。
  - 调度画像：`role`、`resource_profile`。
- 索引：
  - `assignment_runtime_idx (runtime_id, assignment_status)`。
- 典型使用：
  - `PostgresControlStateStore.assign()` 建立分配。
  - `finish_assignment()` 标记完成或失败。

### 5.4 `control.runtime_instance`

- 用途：登记可用 Runtime 实例及其能力、心跳状态。
- 主键：`runtime_id`。
- 关键字段：
  - `runtime_type`、`role`、`node_id`。
  - `capabilities`、`status`、`capacity`。
  - `started_at`、`last_heartbeat_at`。
- 典型使用：
  - `register_runtime()` 注册/刷新实例。
  - `heartbeat()` 更新心跳。

### 5.5 `control.capacity_reservation`

- 用途：记录某个资源范围的容量预留。
- 主键：`scope`。
- 关键字段：
  - `reserved`：当前已保留额度。
  - `updated_at`：最后更新时间。
- 典型使用：
  - `reserve_capacity()` / `release_capacity()`。

### 5.6 `control.runtime_checkpoint`

- 用途：保存运行时检查点，支持恢复执行。
- 主键：`(tenant_id, session_id, run_id)`。
- 关键字段：
  - `fencing_token`：写入时要求租约仍有效。
  - `phase`：当前执行阶段。
  - `state`：恢复所需状态快照。
  - `updated_at`：检查点时间。
- 典型使用：
  - `save_checkpoint()` 与 `load_checkpoint()`。

### 5.7 `control.runtime_cancellation`

- 用途：记录取消请求。
- 主键：`(tenant_id, session_id, run_id)`。
- 关键字段：
  - `requested_at`：取消请求时间。
- 典型使用：
  - `request_cancel()` 写入请求。
  - `is_cancelled()` 查询是否已被取消。

## 6. delivery

### 6.1 `delivery.delivery_job`

- 用途：结果投递主任务表。
- 主键：`delivery_id`。
- 唯一约束：`(event_id, sink_id)`。
- 关键字段：
  - 关联信息：`event_id`、`tenant_id`、`root_session_id`、`session_id`、`run_id`。
  - 投递目标：`sink_id`、`sink_type`、`sink_target_ref`。
  - 内容与状态：`payload_ref`、`status`、`attempt_count`、`next_attempt_at`、`last_response_summary`。
  - 生命周期：`created_at`、`completed_at`。
- 索引：
  - `delivery_job_due_idx (next_attempt_at, delivery_id) WHERE status IN ('pending', 'retry_wait')`。
- 典型使用：
  - `PostgresDeliveryJobStore.create_job()` 创建投递任务。
  - `claim_due()` 拉取可执行任务。
  - `record_attempt()` 回写结果并驱动重试/死信。

### 6.2 `delivery.sink_config`

- 用途：租户级结果投递目标配置。
- 主键：`(tenant_id, sink_id)`。
- 关键字段：
  - `session_id`：所属任务或根任务。
  - `sink_type`、`target_ref`、`credential_ref`。
  - `event_types`：订阅的事件类型集合。
  - `enabled`、`created_at`、`updated_at`。
- 索引：
  - `sink_config_session_idx (tenant_id, session_id, enabled)`。
- 典型使用：
  - `register_sink()` 注册或更新配置。
  - `list_sinks()` 查找某任务在某事件上的有效投递目标。

### 6.3 `delivery.delivery_attempt`

- 用途：投递尝试明细表。
- 主键：`(delivery_id, attempt_number)`。
- 外键：
  - `delivery_id -> delivery.delivery_job(delivery_id) ON DELETE CASCADE`。
- 关键字段：
  - `started_at`、`completed_at`。
  - `outcome`、`response_summary`、`retryable`。
- 典型使用：
  - `PostgresDeliveryJobStore.record_attempt()` 每次投递后落一条尝试记录。

## 7. security

- 用途：登记工具能力与风险元数据。
- 主键：`(tool_name, version)`。
- 关键字段：
  - `description`、`input_schema`、`output_schema`。

  - `provider`、`account_scope`、`allowed_operations`。

### 7.4 `security.credential_usage_audit`

### 9.3 `observability.audit_event`

- 用途：审计事件。
- 主键：`audit_id`。

  - `resource_ref`、`payload_ref`、`metadata`。

### 9.4 `observability.alert`

- 用途：告警事件与当前状态。
- 主键：`alert_id`。
- 关键字段：
  - `rule`、`severity`、`status`、`summary`、`fired_at`。
  - `tenant_id`、`root_session_id`、`session_id`、`run_id`、`labels`。
- 索引：
  - `alert_status_time_idx (status, fired_at DESC)`。
  - `alert_session_idx (tenant_id, session_id, status)`。
- 典型使用：
  - `PostgresObservabilityStore.write_alert()`，同一 `alert_id` 可更新状态。

### 9.5 `observability.retention_policy`

- 用途：数据保留策略配置。
- 主键：`data_class`。
- 关键字段：
  - `retention_days`：保留天数。
  - `updated_at`：最后更新时间。
- 初始化数据：
  - `metric = 30`
  - `trace = 14`
  - `audit = 365`
  - `alert = 90`

## 10. 关系与流转摘要

### 10.1 主业务流

1. API/应用层命令进入后，事件首先落到 `session_core.canonical_event`。
2. 事件追加时同步写入 `session_core.outbox`，再驱动投影或结果投递。
3. 投影器将事件消费为 `projection.task_view`、`projection.approval_view`、`projection.collaboration_view` 等读模型。
4. 控制面把可运行任务写入 `control.runnable_item`，并通过 `control.assignment` 与 `control.runtime_lease` 驱动 Runtime 执行。
5. 结果投递通过 `delivery.sink_config` 解析目标，生成 `delivery.delivery_job`，并将尝试记录写入 `delivery.delivery_attempt`。
6. 全链路过程中，Trace、Metric、Audit、Alert 分别进入 `observability` schema。

### 10.2 设计特点

- `session_core.canonical_event` 是唯一任务事实源，其他视图都可重建。
- `projection.*_view` 明确是读模型，允许删除后从事件流重放恢复。
- `control.*` 侧重运行时资源调度，与业务 Session 状态解耦。
- `security` 与 `artifact` 承担治理和审计责任，不直接承载主业务流程状态。
- `observability` 与业务表通过上下文字段关联，而非大量外键强绑定。

## 11. 建议补充

当前迁移脚本中，大多数跨表关联通过业务字段约定实现，数据库层外键较少。这种设计有利于事件驱动与可重建投影，但如果后续需要增强 DBA 视角的可维护性，建议继续补充以下资料：

- 一份 ER 图，展示按业务含义的逻辑关联而非仅物理外键。
- 一份字段字典，补充每个 JSONB 字段的结构约定。
- 一份生命周期文档，说明各状态字段的合法状态机。
